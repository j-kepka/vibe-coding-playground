# Working here

- This playground documents development with Codex. Follow the user's current request and the relevant project's public documentation.
- Before working on a project, read its AGENTS.md and README.md.
- `01-prismellow/` contains Prismellow, the original independent match-three game. Preserve its game code and assets unless the user requests a change.
- The root README introduces the projects. Each project's README explains its motivation and how to run it.
- Keep each project's concise case study in its top-level `AI_TRANSFORMATION_OUTCOMES.md`. Use the shared [template](methodology/AI_TRANSFORMATION_OUTCOMES_TEMPLATE.md) and [playbook](methodology/AI_TRANSFORMATION_OUTCOMES_PLAYBOOK.md). Report results for the correct implementation and identify the source of estimates.
- Public documentation uses English and references only available public materials. Game interface translations may use Polish and German.
- Write personal project narratives in first person singular (`I` / `my`). Attribute Codex's implementation and checks explicitly; keep shared methodology and technical instructions neutral.
- Keep the delivered project usable and understandable from its public files alone. Record lasting decisions, verification results and relevant limitations there in concise form.
- Describe actual iterations, checks, errors, corrections and limitations. Label translated requests, historical feedback and retrospective accounts honestly.
- Treat historical reports and earlier milestone tags as records of their time. Do not rewrite them to match today's paths.
- Build and verify one coherent iteration at a time. Keep documentation proportional to completed work; do not invent playtesting feedback, dates or productivity measurements.
- Use the confirmed local Git author when commits are requested. Publication and license decisions belong to the owner.
